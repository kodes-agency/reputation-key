## What the code says

Read at `6aa621781`; each shapes a decision below.

- **Most columns need no server change.** `propertiesQuery` (`route-queries.ts:28-32`, key `['properties','list']`, 5 min stale) sends the whole `Property`: `address: string | null`, `countryCode`, `googleBindingState` (`unbound | account_confirmation_required | active | disconnected`), `lifecycleState`, `purgeScheduledFor`. It has eight other consumers (sidebar, inbox scope, notifications, members, portals, setup wizard), so it is read, never reshaped.
- **There is no city.** Google's `locality` is parsed and then flattened into one string by `addressFrom` (`google-business-information.adapter.ts:61-72`), and users may edit it at import (`google-import-review-row.tsx:126`). Parsing a city back out is unreliable.
- **The attention signals overlap.** `overdue` (open, measured Google review targets past `due_at`, filled in by the use case, `get-fleet-overview.ts:90-94`) is a subset of `itemsToTriage` (every open inbox item, adapter `:482-484`); `escalated` (unresolved, open or closed, `:485-488`) overlaps both; `goalsBehindPace` (`:491-541`) is disjoint. `needsAttention` is `count(DISTINCT work_key)` (`:542-552`). A breakdown must never read as a sum. `ratingDrop` is always false for `'all'` (`get-fleet-overview.ts:97-107`).
- **Inbox deep links.** `itemsToTriage` equals the `open` queue exactly, `escalated` the `escalated` queue (`inbox/application/inbox-queues.ts:75-82`); no queue matches `overdue`. `/properties/$propertyId/reviews` accepts `queue` (`reviews.tsx:25-35`) and needs only `inbox.read`, whereas `/inbox?propertyId=` needs `inbox.manage` (`inbox/index.tsx:22-27`). The manager rail does not list `open` (`components/inbox/inbox-queues.ts:36-43`), so `?queue=open` shows the right list with no rail item highlighted.
- **Setup summaries throw the steps away.** `listPropertySetupSummaries` runs `derivePropertySetup` per property and returns `{ propertyId, attentionCount }` only (`list-property-setup-summaries.ts:8-12, 48-51`); its only consumer is this route. The client already counts complete + deferred as done (`property-setup-steps.ts:40-44`), and `property-setup-strip.tsx:51-70` already maps a step to its link (portals → `/portals`, else `/settings/<section>`).
- **The org checklist writes on read.** `setup-checklist.repository.ts:178-184` inserts milestones (`onConflictDoNothing`) whenever the checklist is read; the milestones table is in the org export and the data-fate registry. This page is its only reader (`index.tsx:59-64, 80, 98`).
- **Lifecycle.** `suspended` is labelled **Paused** (`property-lifecycle-model.ts:29-37`); there is no suspend command. Remove / Restore live only in Settings › Danger zone (`settings/danger.tsx`) and need `property.archive` + `property.disconnect` / `property.restore`, which only AccountAdmin holds (`shared/auth/permissions.ts:71, 77`). `purgeScheduledFor` is the **self-service restore deadline**, not a deletion date (`use-cases/property-lifecycle.ts:91, 158-166`); `formatPropertyRecoveryDeadline` formats it (`property-lifecycle-model.ts:54-66`). `ConfirmationDialog` has no `open` prop (`property-lifecycle-confirmation-dialog.tsx:16-59`).
- **Automated pins.** `beta-product-journeys.spec.ts:1133, 1175` require the URL to match `/\/properties$/` (no query string by default); `:1137-1147` find each row as `getByRole('link').filter({ hasText })` and read `/(\d\.\d)\s*★/` inside that link; `auth-and-shell.spec.ts:52` and `:1160` match property names in strict mode, so a name may render **once**. `accessibility.spec.ts:64-108, 516-562` run full axe (dark, light) and a 320 px reflow check (page width ≤ window + 8). Storybook's test runner compiles no CSS (`e2e/storybook-metrics/story-matrix.ts:8-10`), so a hidden duplicate layout is visible there too.
- **Gates.** `react-hooks/incompatible-library` is an error (`eslint.config.js:490`) and flags TanStack Table's `useReactTable`. Components may not value-import `contexts/*/server` (`check-component-boundaries.mjs:55`). `max-lines` 300 counted for `src/components/**` (`eslint.config.js:871-888`). Non-literal `useState` initialisers need a ledger row (`check-product-state-consistency.ts:693-714`). Zod from `zod/v4` only. Unit tests are `*.test.ts` only (`vitest.config.ts:103`). Fallow fails on findings the PR introduces, including unused files and exports (`.fallowrc.json` rules).
- **Bundle.** The route component is split into a lazy chunk (TanStack Start code splitter); only the 128,000 B per-chunk cap applies. The initial closure has ~2.4 KB headroom (`check-bundle-budget.mjs:30-32`), so nothing new may be imported from `_authenticated.tsx`'s graph.

## Amended during implementation

Each amends the row named; the code is the reference.

1. **Google is not a column** (row 5): linked is the norm and "Linked" on every
   row was noise. A property that is not linked says so on the Property cell's
   second line — `Google not linked` / `Confirm the Google account` /
   `Reconnect Google`, warn ink with an icon — linking to its Google settings;
   the strip's Google figure and the Show filter still cover the portfolio.
2. **Link ink** (rows 4, 7, 8): the name keeps the link accent — the row's one
   way in. The attention and setup cells are links too, but `styles.css`'s
   global `a` colour is unlayered and beats utilities, so those links (and the
   row-menu items) pin their ink with `text-foreground!`.
3. **Next setup step** (row 15): the viewer's `pending` step with a section,
   else a `needs_admin` step, else a `pending`/`waiting` step. A pending step
   with no section is only the first sync while Google is unlinked, which nobody
   can do directly, so "waiting on an account admin" is the truer pointer.
4. **Stacked below a 56 rem container** (row 2), by container query rather than
   viewport, so the app sidebar's width decides it; the Removed table stacks
   below 48 rem.
5. **Restore copy** (row 16): `Restore before Oct 3, 2026` (the card's
   "available before"), and `Ask support to restore` past the window or with no
   deadline recorded.
6. **The breadcrumb that repeated the title is gone**; the description is
   `6 properties · 1 paused`.
7. **The Sort menu carries direction** (row 12) — "Most first / Fewest first",
   "A to Z / Z to A", "Least done first / Most done first" — because the stacked
   layout has no headers to click. A direction written for the default sort is
   kept even though the URL omits that sort (review fix on #587).
8. **An attention total with nowhere to link** (row 7) — only possible with a
   rating drop on a bounded window — prints the figure without a link rather
   than "Nothing waiting".
