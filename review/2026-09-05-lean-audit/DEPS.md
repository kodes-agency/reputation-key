## Node / pnpm pinning

- `.nvmrc` = `engines.node` = `22.23.2` exactly; `packageManager pnpm@10.6.5`; `.npmrc` documents why `engine-strict` and a `preinstall` guard were removed (both broke CI/Docker). The pin is enforced at build time in all Dockerfiles (`Dockerfile:72,142`), by `local:doctor`, by `stack.ts`, by `pinned-runtime.test.ts`, and by 4 byte-attested generated files that `.prettierignore` refuses to format because regenerating them "can only be done on node 22.23.2 / ICU 78.2". Bumping Node therefore means touching 153 files and regenerating 4 attested artifacts on the old runtime first. That is the friction: the pin protects deterministic language-detection tables that exist because `cld3-asm`/ICU behaviour is treated as a governance control. Decision: keep the exact pin in the Dockerfile only; make host tooling warn, not refuse; drop the byte-attestation tests so a Node minor bump is a one-line change.
