## What it missed or got wrong under the one-developer lens

- **It kept the four sidecars and their four serving pipelines as "proportionate" (`OPS.md:75-102`).** That is now decided against. With web+worker only, the following exist solely for the sidecar topology: 7 of 10 Dockerfiles, 10 of 12 `tsup.*.config.ts`, 6 of 10 `railway*.json`, the `sidecars` docker matrix group and its five smoke contracts (`.github/workflows/ci.yml:447-455,567-640`), `check:google-runtime-bundle`, `verify-ai-runtime-image.mjs`, `smoke-provider-redis-image.sh`, `check:ai-contract-attestations` (521 lines pinning `openai`/`undici` bytes), `check:ai-governance-artifacts`, 6 of the 8 release-image matrix roles (`release-images.yml:100-132`), and the `RELEASE_SHA` blocker that broke the digest cutover (`closed-beta-ci-image-delivery.md:20-52`, `services/google-egress-gateway/environment.ts:137,176`).
- **It never asked who merges dependabot.** 20/20 dependabot runs fail; 37/60 PRs closed unmerged; the last merges were a hand-driven batch on 2026-08-21. The cause is self-inflicted triple pinning: `check:technology-stack` demands 41 exact versions in `security/technology-stack.json` (`scripts/ci/check-technology-stack.ts`, 1,009 lines; log: "32 violation(s): @tanstack/react-query must be declared exactly as 5.101.4; found 5.102.8"), plus a unit test that hard-codes `openai: '7.4.0'` (`src/shared/ai-canonicalizer-attestations.test.ts:52-65`), plus action SHAs re-listed in the same JSON so even a `setup-buildx-action` bump fails `static` (run 33945785086). A solo developer now has to edit three authorities per patch bump; the observed result is that patches do not land at all, which is a worse security posture than `^` ranges plus the audit gate (G005).
- **It measured the E2E pole but still recommended keeping all three suites on every PR (`GATES.md:164-172,376-378`).** `e2e` is 736 s of a 741 s PR; every other job would finish inside ~6 min. Five of the nine inspected developer-branch failures were critical-E2E, two of them on `main` with `--fail-on-flaky-tests` (`ci.yml:1044`), and the same `reply-lifecycle.spec.ts:460` signature ("Reply status changed concurrently") failed on two different branches within 24 h — the suite is finding real races (`3b364e9d`, `f3d9baac` followed), but it is also the sole reason a docs commit costs 12 minutes.
- **It treated `--fail-on-flaky-tests` on main as useful (`GATES.md:320`).** With one developer, a red `main` after a green PR has no reviewer to route to; it just blocks the next deploy (`deploy-ci-images.ts:566-576` refuses without a successful main run). Retry-once on main with the flake register (`docs/operations/e2e-flake-register.md`, 6 rows) is the proportionate control.
- **It did not name the 24 zero-reference npm scripts.** Nothing in CI, hooks, docs, `src`, `scripts`, Dockerfiles, `.railway`, or `.github` references: `dev:all`, `build:local-tools`, `build:google-egress-gateway-local`, `preview`, `lint:fix`, `test:watch`, `test:e2e:local`, `e2e:stack:smoke`, `local:stack:smoke`, `local:stack:logs`, `local:beta:up`, `seed:simulate`, `db:pull`, `perf:seed-fleet`, `beta:create-pre-cutover-dump`, `release:create-promotion-manifest` (workflow calls the file via `tsx` directly, `release-images.yml:315`), `release:google-import-drill`, `review:freeze-baseline`, `review:validate-pre-fix-oracles`, `generate:google-provider-fixtures`, `generate:ai-governance-artifacts`, `ops:google-credential-routing-publish`, `ops:reconcile-recent-activity-vocabulary`. Keep `dev:all`, `lint:fix`, `test:watch`, `preview` as human conveniences; the other 20 are dead.
- **It undercounted ceremony living in `src/`.** `src/shared/release` (17,877 lines) and `src/shared/governance` (23,286 lines) are release/catalogue apparatus shipped inside the application tree and typechecked/tested on every PR; GATES.md counted only the 6,348+3,044-line catalogues (`GATES.md:245`).
- **It said the pre-push trio "should be deleted" but described them as live (`GATES.md:260-262`).** They were deleted the same day (`4085491e`). The only local hook left is `lint-staged` (`package.json:287-299`), which is fine.
- **Branch protection moved after the review:** `strict:true` and CodeQL are now required (6 contexts). Strict + a 12.6-min main run means every merge behind another merge costs a full re-run; for one developer that is pure tax.
- **`ops:*` is 57 scripts of which 30 are `report-*`/`reconcile-*`/legacy-contraction one-offs** referenced by ≤3 docs each and touched once in 60 days (git churn table: 33 files with ≤1 commit). They are not operations; they are migration receipts.

## The minimal release path (proposal)

1. **PR CI = `static` + `test-unit` shards + `test-integration` + `artifacts` + `secrets` + `docker(web,worker)` → `check` (target ≤ 7 min).** Replaces: `e2e` on every PR (736 s), `storybook`/`storybook-test` (245 s), the `sidecars` and `worker-tools` docker groups, `beta-acceptance` label path, and the CodeQL/Fallow/Simulation required contexts. Keep the aggregate name `check` so protection does not need re-migration (`GATES.md:50`).
2. **Merge to main (drop `strict`).** Replaces: forced re-runs on every stacked merge.
3. **Main CI = the same jobs + critical E2E (retries:1, no `--fail-on-flaky-tests`) + `docker` pushes `repkey-web` and `repkey-worker` by digest to GHCR and writes the digest map** (already implemented, `ci.yml:709-757,822-895`, shrunk from 7 images to 2 and the `jq` expected list at `ci.yml:797-800`). Replaces: `release-images.yml` (354 lines, 0 runs), `create-promotion-manifest.ts`, cosign/SLSA/toolchain pinning, `beta_evidence_manifest_sha256` and `provider_approval_evidence_sha256` inputs.
4. **Deploy = `pnpm ops:deploy-ci-images <sha> --live --apply`** (already implemented, 1,020 lines; strip `--operator/--reason/--ticket/--yes <command-name>` ceremony to `--sha` and `--apply`). Railway pulls the digest; `preDeployCommand` runs `migrate-deploy` (`railway.json:9`); readiness is `/api/health/ready` (`railway.json:10`). Replaces: `deploy-beta.ts` (2,428 lines), `freeze-release-candidate.ts`, `capture-promotion-readback.ts`, `staged-railway-sources.ts`, `railway-data-cell-*.ts` (2,203 lines + tests), `bootstrap-schema-migrator.ts` (1,025 lines: the migrator becomes the preDeployCommand it already is), the `.railway/*.ts` IaC (1,952 lines) and the six migrated `railway*.json` sidecar files.
5. **Post-deploy = one `curl` of `/api/health/metrics` asserting `jobs.ready=true` and `degraded=[]`** (the snapshot OPS.md already praised, `OPS.md:65-73`) folded into the tail of `deploy-ci-images.ts`. Replaces: `observe-canary-window.ts` (599), `run-deployed-critical-journeys.ts` (729), `rehearse-recovery.ts` (450), `import-live-evidence.ts`, `prepare-gate-f-approval.ts`, `validate-bundle.ts`, `promote-local-evidence.ts`, `create-legal-revision-set.ts`, and the Gate F/live-evidence/legal-approval modules in `src/shared/release` (~14 k of 17,877 lines).
6. **Rollback = re-run step 4 with the previous SHA.** The digest map for every main SHA is retained 90 days (`ci.yml:888-895`). Replaces: the per-service rollback table and hand procedure in `closed-beta-ci-image-delivery.md:270-288`.
7. **Nightly workflow (new, ~60 lines) = full+compatibility E2E, storybook-test, CodeQL, Fallow, simulation, dependency/licence audit, on `schedule` against `main`, notifying by e-mail/Sentry on red.** Replaces: `codeql.yml`, `fallow.yml`, `simulation.yml` as PR workflows (they stay as jobs).

Net: `scripts/release` 18,666 → ≈ 0 lines (the two survivors, `iac-digest.ts` and `release-authority-digest.ts`, go too once IaC is gone); `release-images.yml` deleted; `.railway/` deleted; `src/shared/release` ≈ 17,877 → ≈ 1,500 (keep `json-shape-guards.ts`, `promotion-manifest.ts` only if the digest map keeps a schema); `ci.yml` ≈ 1,265 → ≈ 500. The work already done on `feat/ci-publish-images` (`280a24a2`) is 80 % of this path; the remaining 20 % is deleting what it replaced.

## Proposed PR gate set vs nightly vs pre-release

**Every PR (≤ 7 min wall, ≈ 25 runner-min):**

- `static`: `check:dependency-audit`, `check:action-pins`, `format:check`, `typecheck`, `lint` (eslint + boundary proof G013 + component boundaries G015 + filenames + zod + product-state) — drop `check:technology-stack`, `check:container-images`, `check:licenses`, `check:test-quality`, `check:ai-*`, `check:google-provider-fixtures`, `check:legal-registry`, `check:runtime-environment-contract` from this path.
- `test-unit` (4 shards) and `test-integration` with migrations + `db:migrate-deploy` parity + `check:schema-drift` (G024–G027) — the real defect-catching core.
- `artifacts`: web + worker build, `check:security-headers`, `check:language-verifier`, `check:bundles` (caught the Sentry SDK regression on 2026-09-04), `check:production-artifacts` — drop the four sidecar builds, compatibility build, `check:google-import-artifacts`, artifact digest (G039), source SBOM (G040/G041).
- `docker`: build + smoke `web` and `worker` only (2 images, ≈ 130 s), grype on those two.
- `secrets` (gitleaks on PR range, 36 s).
- `check:coverage` moves to main-only: it is the slowest single unit job (368 s) and its ratchet has one documented catch (`d9a2a475`, `GATES.md:285`).

**Main push (adds ≈ 6 min):** `check:coverage`, `check:changed-code`, critical E2E with `retries:1` and no `--fail-on-flaky-tests`, image push + digest map.

**Nightly (scheduled, non-blocking, e-mail on red):** full + compatibility E2E, `storybook` + `storybook-test`, CodeQL, Fallow, simulation (`pnpm simulate`, not `seed`), `check:licenses`, `check:dependency-audit` on the full tree, `check:test-quality`.

**Pre-release (manual, only when the change touches migrations, auth, or Google effects):** `beta:smoke` clean/upgrade/fault lanes (`ci.yml:1117-1213`, ≈ 8 min in parallel) run via `workflow_dispatch`; a restore drill against a Railway backup once a quarter (`ops:restore-preflight`/`ops:restore-verify`). Everything else in Gate F is retired.
