## What it missed or got wrong under the one-developer lens

- **It recommended keeping the machinery and fixing it; a solo dev should delete it.** DOCS.md "keep the three-state matrix" (`GATES.md:80`), "retain the three axes and zero-closure headline" (`DOCS.md:62`), "deepen existing ledger schema" (`DOCS.md:247`). Each of those is a self-imposed authority with no external requirer and no product reader.
- **`capability-fate.ts` is a mirror, not the authority.** The review called it "the best artifact in the repository" (`README.md:18,120`). It has one production importer (`src/shared/auth/capability-refusal-category.ts`), used to label refusals. The runtime decides from `CORE_CAPABILITIES`/`BLOCKED_CAPABILITIES` in `src/shared/auth/beta-capabilities.ts` (660 lines). Two hand-kept lists of the same 37 keys; `capability-fate.test.ts` (82 lines) exists to keep them agreeing. The fix is to make the fate table generate the runtime sets, not to admire it.
- **`GATE_POLICY` is now dead code.** The CLI that read it was deleted in `4085491e` (`scripts/ci/gate.ts` −158); the 282-line registry survives with zero importers. Worse than the review's "unused second authority": an unused zero-th one.
- **ADR 0050 §11 approval bindings caused a real outage the review did not price.** `docs/operations/google-content-approval-closed-beta.md:8-12`: on 2026-08-31 a route-catalogue version bump invalidated every Ed25519-signed role bundle and `web`/`worker` refused to boot. Five role documents signed by one person (`docs/adr/0050-…md:250,379-387`) bought nothing and cost a production outage. That is the strongest single argument for retiring self-imposed attestation.
- **ADR 0059 binds a release profile to the ADR file's own SHA-256** (`docs/adr/0059-…md:44-47,110-112`): editing the decision record invalidates the canary profile until re-ratified. Same class as the S7 prose-coupling finding, unflagged.
- **The Google written response is the only external requirement document in the repo, and DOCS.md:227 recommended archiving its folder.** `docs/product-readiness-program-2026-07/google-business-profile-ai-policy-response-2026-07-14.md` sits in a folder whose README calls itself a "Historical program index" (`…/README.md:3`). Archiving the tree buries the one file that imposes anything.
- **ADR 0031 — the ADR that encodes that external response — is still `status: proposed`** (`docs/adr/0031-…md:2`) while 21 source files cite it. The most externally load-bearing decision has the weakest status.
- **Production source comments cite dated evidence markdown.** `src/shared/auth/beta-capabilities.ts` references `docs/release-evidence/review/safe-01-independent-security-review-2026-08-28.md` and `comprehensive-progress-report-2026-08-28.md`; five `scripts/review/*.test.ts` files and `scripts/perf/*` pin `docs/release-evidence/**` paths. Evidence is not "segregated from navigation" (`DOCS.md:231`); it is compiled in.
- **A 775-line TypeScript module exists to assert that sentences occur verbatim in markdown.** `src/shared/governance/counsel-decision-checklist.ts` reads `docs/legal/implementation-facts-2026-08-26.md` (10 references) and `docs/security/data-inventory.md`; `itemAnchorErrors` (`GATES.md` G107) checks anchors. No production importer.
- **The review's CONTEXT.md sample judged posture, not mechanics.** My check of the five I sampled (below): Notification's 22-row "events consumed" table is fully accurate (22/22 tags present in `src/contexts/notification`), but Property's "Events consumed: None" sits beside `src/contexts/property/infrastructure/outbox-consumers.ts` and `property-retention-outbox-consumer.ts`. Accuracy is high where the table is short and drifts where it mirrors registrations.

1. **What the beta is** — one Organization (Fortunatus EOOD), six Properties, one developer/operator, one Railway project, one US cell; `CURRENT_RELEASE_POSTURE = 'closed-beta'` (`src/shared/release/release-posture.ts:46`) and what widening it requires.
2. **External obligations (the only non-negotiables)** — Google written response 2026-07-14 (link): per-property AI only, PII removed before egress, no training, raw content refreshed/removed on the 30-day policy, human manual publish, no cross-property summaries, no review-solicitation gamification; Google API policy: Performance values live-only, no gating of the review link; OAuth web-server flow with exact redirect URIs; GDPR: accurate privacy notice before any third-party data subject beyond the owner's own profile.
3. **Product contract** — the current §3.1–3.7 of the program, compressed to ≈40 bullets: invitation-only manager roles; Portal rating-first with threshold-offered private feedback; stable Review identity, Handling Cycles, `open|closed`, Response Target 48 h stopped only by `confirmed_on_google`; three AI capabilities advisory only; rolling-30-day reporting, never coerce missing to zero; recognition/Team/custom roles/billing/Staff login OFF.
4. **Capability authority** — "`src/shared/governance/capability-fate.ts` is the single table; the runtime derives its sets from it. Live state today: 24 ON / 13 OFF."
5. **Architecture rules that are enforced (and where)** — context boundaries (eslint + boundary-controls script), atomic state+fact (outbox tests), tenant predicate canary, server-only import protection, no ambient clock in domain, identifier-only facts. Nothing listed here without a test or lint path.
6. **Release checklist (replaces Gate F)** — CI green on the SHA (required checks manifest); migration applied by `db:migrate-deploy`; deploy the CI-built digest; `/api/health` 200; one authenticated journey (Google review → Inbox → Confirm & Publish → observed) on the deployed cell; PITR backup verified in the last 30 days; 24 h watch of health/Sentry/outbox before "done".
7. **Operating commitments** — support hours (Mon–Fri 09:00–18:00 Europe/Sofia), RPO ≤15 min / RTO ≤4 h, the seven stop conditions from ADR 0038, one alert sink that reaches a phone.
8. **What is deferred and why** — the `beta_disabled`/`safety_blocked` rows with their activation conditions, copied from the fate table (or generated).
9. **Precedence** — external obligations → this page → ADRs (24) → `docs/standards.md` → code. Anything under `docs/archive/` is provenance.
10. **Change log** — dated one-line entries; this is the "ledger".
