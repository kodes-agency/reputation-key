## Regime for every WP

- **One branch and one pull request per WP**, base `main`, squash-merged (`required_linear_history: true`). Branch `lean/wp3-<n>-<slug>`. `enforce_admins` is on; nothing bypasses the six required checks (`check`, `docker`, `e2e`, `secrets`, `audit`, `Analyze (javascript-typescript)`).
- **Local gate before each commit**, on the pinned runtime (`fnm exec --using=22.23.2 --`): `pnpm typecheck && pnpm lint && pnpm test:unit`. Add `pnpm test:integration` when `src/shared/db/**`, any `*.schema.ts`, `drizzle/`, or a repository/command store changed. Add `pnpm build && pnpm check:bundles` when `vite.config.ts`, `src/routes/**` or `src/components/**` changed. Add `pnpm test:storybook` when stories changed (`pnpm test-storybook` no longer exists — see WP3.6).
- **Schema changes are never hand-written migrations.** Edit `src/shared/db/schema/*.ts`, `src/shared/db/db-constructs.sql` and `src/shared/db/db-seed.sql` (the three sources), then `pnpm db:baseline && pnpm db:reset && pnpm check:schema-drift "$DATABASE_URL"` (must print `No schema drift detected`). `scripts/db-baseline.ts` wipes `drizzle/`, runs drizzle-kit for `0000_baseline.sql`, and **byte-copies** the two SQL sources to `0001_db_constructs.sql` / `0002_db_seed.sql` — it derives nothing, so any digest or literal inside those SQL files is edited in `src/shared/db/` first. Never edit `drizzle/**` by hand.
- **Three hand-maintained registries break on every table deletion** and are edited in the same commit: `src/shared/governance/data-fate-authority.ts` (one `{schemaFile, exportNames[]}` row per table), `src/shared/db/migration-verification.test.ts` (hardcoded table-name list at `:64-79+`), and `src/shared/db/schema/index.ts` (37 `export *` lines). `src/shared/db/schema/db-only-constructs.ts` parses trigger/function names out of `db-constructs.sql` and self-updates — only its `UNPARSED_CONSTRUCTS` list (`:69-79`) is manual.
- **Every deletion names its replacement or its evidence of having none.** The reviewer on every PR asks, per removed check: what gated this before, what gates it now, is the replacement live per-request or a stored snapshot, did a deleted test lose its subject or its coverage. Write each PR body to answer those four questions.
- **Run the app after each WP that touches routes, schema or the worker:** `pnpm db:reset && LOCAL_TOOL_EXECUTION_IDENTITY=repkey-local-stack-v1 PORTAL_TOKEN_HASH_SECRET=$(openssl rand -hex 32) pnpm seed:e2e-user && pnpm dev`; log in as `test@example.com` / `password123`; load `/dashboard?timeRange=30d`, `/inbox`, `/settings/integrations`, `/settings/ai`; confirm `/api/health/ready` is 200 and no 5xx appears in the server log. - **No WP edits `.github/workflows/review.yml`** — the action refuses to run when that file differs from `main`.
