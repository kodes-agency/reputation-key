## What the Sept 2 review already found

- The scale itself — 242 tables, 39 enums, 491 indexes, 707 checks, 316 FKs, 114 functions, 142 triggers, "40.3 tables per live Property" (`review/2026-09-02-state-of-the-app/DATA.md:5`, `:310`), with every table classified as 189 active / 6 write-only / 8 evidence / 39 legacy (`:34-58`).
- The dead rollup subsystem still scheduled (`DATA.md:257-269`) — **now closed**: `313302b6` / `drizzle/0181_big_killmonger.sql:1-4` dropped all four tables.
- Six written-but-never-read tables with the two uniqueness receipts distinguished (`DATA.md:49`, `:116-124`, `:289-304`); `review_sync_runs` delete-only (`:58`).
- `migratable.ts` omitting 12 lifecycle/privacy tables (`DATA.md:180-201`) — **now mostly closed**: only the five `google-import-compatibility` tables remain outside the barrel (snapshot 225 vs 230 app tables).
- Migration weight priced (34,270 lines; 0177 = 924 lines for four predicate removals, `DATA.md:219-221`, `:312`) and 71 synthetic future journal timestamps (`:231-241`).

## What it missed or got wrong under the one-developer lens

- **It priced the journal and then told you to keep it.** "Do not rewrite the applied journal" (`DATA.md:227-229`) and "do not renumber applied entries" (`:239`) are fleet advice. There is one production database; `drizzle.__drizzle_migrations` is one table the staged migrator writes one row per entry into (`src/shared/db/staged-drizzle-migrator.ts:269-273`) and the drift check compares by hash (`src/shared/db/schema-drift.ts:655-671`, `:1179-1182`). A squash is a baseline file plus one row reset.
- **It never asked whether the 115 functions and 141 triggers should exist.** Only 35 functions are called from TypeScript; 103 of 141 triggers exist to stop the application from mutating rows the application itself wrote (append-only/immutability guards). With one web process and one worker running the same code, that is a second implementation of every invariant, written in a language with no type checker, tested only by 44 integration test files that need a live PostgreSQL.
- **"Has a reader" was treated as "active."** 51 governance/evidence tables and 20 AI-ceremony tables have readers only in governance, lifecycle, or sidecar code: `backup_erasure_*`, `property_erase_*`, `context_/identity_organization_lifecycle_receipts`, `organization_lifecycle_command_receipts`, `privacy_*`, `review_lifecycle_recovery_executions`, `review_sync_runs` all have **zero non-governance referencing files** (usage script, `nonGov=0`). Nothing a manager sees depends on them.
- **It endorsed the contraction gate as "honest about preconditions"** (`DATA.md:126-134`). The measured price: 62 files and 44k lines to drop four tables with 21 rows (`313302b6`). That gate is the reason the 38 legacy tables are still here.
- **It missed the migration process debt entirely**: 57 hand-written migrations with no snapshot, the `0179` no-op alignment migration (`drizzle/0179_magenta_sharon_carter.sql:1`), 46 function redefinitions with one `DROP FUNCTION`, the untracked `drizzle.bak/`, the never-applied `better-auth_migrations/`, 12 orphan `scripts/migrations/*.sql`, and a migrator that hard-codes two historical special cases (0033 enum commit boundary and a review-source backfill keyed on a millisecond, `staged-drizzle-migrator.ts:9-13`, `:135-141`, `:260-266`).
- **Three goal generations coexist** in 13 tables: `goals`/`goal_progress`, `goal_definitions`/`goal_periods`/`goal_evaluations`, and the live `goal_programs` family; the first two are "migration sources only" (`src/contexts/goal/CONTEXT.md:10-13`, `:59`) yet `goal.repository.ts` still inserts/updates `goals` (4 insert, 5 update sites).
- **The 0140 data-cell fences outlived the cutover.** 15 `*_topology_cutover_fence` triggers on 13 tables (`drizzle/0140_single_us_beta_data_cell.sql:119-130`) fire on every write to `google_connections`, `gbp_import_requests`, `gbp_import_request_items`, permits, etc., to guard a three-cell migration that ADR 0057 says never happened (`docs/adr/0057-single-us-beta-data-cell.md:112-116`).
- **The AI schema is a config file stored as rows.** 12 migrations `INSERT INTO ai_*` catalogue rows (profiles, routing policies, capability profiles, calendar authorities) and then install `reject_ai_catalogue_mutation` triggers on ten tables (`drizzle/0046-0048`) so the rows cannot change except by migration — which is what a TypeScript constant does for free.
- **Better Auth duplication was not examined** (see row 10 below).
